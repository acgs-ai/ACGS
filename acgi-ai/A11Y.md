# Accessibility foundation

This document records the local static accessibility foundation for `acgi-ai`. It is not a WCAG conformance statement.

## Local static gate

Run:

```bash
pnpm run test:a11y
```

The gate verifies the baseline structures that can be checked without browser automation or assistive technology:

- skip links on marketing, product, login, trust, security, privacy, not-found, and console shells
- stable `main-content` / `console-main-content` targets with programmatic focus via `tabIndex={-1}`
- global visible focus styles through `:focus-visible`
- global reduced-motion handling through `prefers-reduced-motion`
- conservative public copy that does not claim WCAG conformance before evidence exists

## Executed axe smoke (console surface)

A real automated axe scan now executes in CI, separately from the static gate
above. The `browser-checks` job in `console.yml` runs
`tests/e2e/a11y-smoke.spec.ts` (via `@axe-core/playwright` against the production
console bundle served by `vite preview --mode console`):

- It scans the console-surface routes `/login` and `/console` with the
  `wcag2a` + `wcag2aa` rule tags and **fails on any serious- or
  critical-impact violation**.
- It is an automated smoke, **not a WCAG conformance statement** and not a
  manual NVDA / VoiceOver pass.
- **Known, intentionally scoped-out debt — `color-contrast`.** The scan
  surfaced a real, pre-existing console-wide deficiency: the control-plane
  `--muted` token (#6c7382) yields 3.7–4.0:1 on the dark console backgrounds
  for small text, below the 4.5:1 minimum (WCAG 1.4.3). The `color-contrast`
  rule is disabled in this smoke so the gate can baseline that known debt and
  still block every other serious/critical violation. The token fix changes
  every muted-text element and needs design review; it is tracked here, **not**
  done in this CI-plumbing slice.

Still not executed (Phase 3 / external): marketing-surface axe, the
`--muted` contrast fix, and the touch-target rule.

## Manual evidence still required

The production accessibility bar remains WCAG 2.2 AA, but the signed evidence is still external to this local static pass and the executed axe smoke above. Full evidence requires:

1. extending the executed axe scan to the marketing surface and resolving the scoped-out `color-contrast` (`--muted`) debt.
2. manual NVDA review of keyboard order, labels, tables, live regions, and error states.
3. VoiceOver review on the same route set and tablet reviewer viewport.
4. full visual baseline matrix and touch-target review for the documented viewport set.
5. legal/product approval before any public conformance wording changes.

Until those artifacts exist, public copy may describe the static accessibility foundation and the executed axe smoke only; it must not state WCAG conformance.
