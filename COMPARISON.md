# gove-zone (kernel) vs the AI-agent governance layer — comparison

> **Scope.** This compares **gove-zone (the kernel)** — the Python enforcement library at `packages/gove-zone` whose core invariant is *"no valid Decision Receipt, no side effect"* — against the real category it competes in: **AI-agent governance / guardrail / authority / audit layers that gate an action *before* a side effect.** The inclusion gate is narrow and behavioral: *is the tool CALLED before a tool call / side effect, and can it return an allow/deny (or transform/escalate) decision plus some evidence trail?* Observability and offline-eval harnesses that only score what an agent already did are out of scope (see the note on LangSmith below).
>
> **Evidence tiering — read this before the table.** gove-zone's cells are **source-verified** against `packages/gove-zone/src/gove_zone/*.py` plus its README / ARCHITECTURE / SECURITY docs. **Every competitor cell is from published vendor docs only — we could not run their code.** Doc absence is not proof of absence: where the docs neither confirm nor deny a property, the cell reads **unknown**, not "no." Competitor data is dated and may be stale (see *Method & limits*).

## What gove-zone is (and is not)

- **It is an enforcement layer, not a product or a SaaS.** A caller — an agent, an MCP tool, a workflow engine, a CI runner — invokes it *immediately before* a side effect. It is a self-hosted Python library (Unix-only; it relies on `fcntl.flock`), stdlib at the core. It is **not** an agent framework and **not** a hosted service.
- **It is Beta (1.0.0rc1).** It is explicitly **not production-certified** and **not compliance-certified**. Every GA/SaaS competitor below is more mature operationally; treat that as a given, not a footnote.
- **It ships no content-safety classifiers.** There is no prompt-injection, jailbreak, PII, or toxicity detector in the codebase (verified — grep finds none). gove-zone is a *policy-evaluation substrate*: **you bring the policy.** It can replay AgentDojo / InjecAgent / ToolEmu-style local fixtures, but it does not classify content. This is a real gap versus the guardrail vendors.
- **Its authority unit is a signed/expiring Decision Receipt, not a capability token.** A receipt binds proposer (actor) vs a distinct validator, carries `expires_at`, an authority grant, and an execution boundary, and is checked by 13 fail-closed `verify()` checks at the gate.
- **Cryptographic signing is OPT-IN and OFF by default.** Ed25519 signing lives behind the `crypto` extra (`signing.py`). The default signer is `NullSigner`, which stamps `signature="unsigned_local"`; an unsigned receipt is **never** signature-valid, and acceptance of unsigned receipts is governed by `require_signature=False` at the gate. There is no PKI, no revocation, no key distribution — the operator owns key custody. So: signed/expiring receipts *exist*, but **default deployments are unsigned.**
- **The runtime-hook adapter is observer-by-default.** Through the canonical integration path (`integration.py`), the adapter emits an `ALLOW` receipt unless the integrator supplies a custom `Policy` **and** sets `GOVE_ZONE_GATE_MODE=enforce` — the default `_ObserverPolicy` always allows, on the principle that the host runtime owns deny. So a **yes** on A1 / A2 / A7 below means *the enforcement mechanism exists and fails closed when wired*, **not** that gove-zone blocks out of the box. Enforcement is integrator-wired.

## Per-competitor notes

**AWS Bedrock Guardrails** *(point solution — content-safety guardrail; GA cloud-managed SaaS).* A managed content-safety layer callable before/after model calls via `ApplyGuardrail`, with filters, PII masking, prompt-attack and contextual-grounding checks ([docs](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-use-independent-api.html)). **Where it exceeds gove-zone:** A6 content safety (managed injection/jailbreak/PII/grounding classifiers gove-zone has none of) and A8 maturity (GA SaaS with SOC/PCI/HIPAA/FedRAMP High vs gove-zone's alpha library). **Where gove-zone differs architecturally:** Bedrock has no proposer-vs-approver authority model, no cryptographic decision receipts or replay, and no hash-chained audit *of the decision content* — CloudTrail's signed hash-chain covers API-call metadata, while the guardrail verdict itself lands in mutable CloudWatch/S3 JSON. It gates on *content*, not on *who is authorized to act* over a *plan*.

**NVIDIA NeMo Guardrails** *(point solution — programmable guardrails toolkit; OSS + production K8s microservice).* Programmable input/output and execution rails that validate tool-call arguments at runtime ([rail-types](https://docs.nvidia.com/nemo/guardrails/latest/about/rail-types.html)). **Where it exceeds gove-zone:** A6 (NIM injection/jailbreak/topic/PII microservices) and A8 (production-ready Helm/K8s deployment, NVIDIA AI Enterprise support, broad LangChain/RAG breadth). **Where gove-zone differs:** NeMo models no authority/identity, ships only OpenTelemetry logs (no tamper-evident audit, A3=no), and has no portable verifiable receipt; its multi-turn rails govern *conversation flow*, not a side-effecting DAG.

**Meta LlamaFirewall (Purple Llama)** *(point solution — content/trace scanner; MIT self-host library).* Runs PromptGuard 2, AlignmentCheck, CodeShield, PII and hidden-ASCII scanners and returns ALLOW / HUMAN_IN_THE_LOOP / BLOCK ([about](https://meta-llama.github.io/PurpleLlama/LlamaFirewall/docs/documentation/about-llamafirewall)). **Where it exceeds gove-zone:** A6 (a deep, ready-to-run classifier suite) and A8 maturity (MIT GA-style OSS v1.0.3 from Meta, OpenAI/LangChain/LangGraph integrations). **Where gove-zone differs:** LlamaFirewall is a *scanner*, not an authority/receipt/audit kernel — it models no proposer-vs-approver, its policy is imperative Python (A5=no), and its audit story is undocumented (A3=**unknown**, transcribed as such rather than rounded to "no"). Its `scan_replay()` re-runs detection over a message trace; it is not a verifiable per-decision receipt.

**Invariant Labs (Guardrails / Gateway / Explorer)** *(point solution — contextual content/dataflow guardrails; self-host MCP proxy, Snyk-backed).* A transparent MCP/LLM proxy that blocks unsafe tool calls using managed detectors and flow rules ([rules docs](https://explorer.invariantlabs.ai/docs/guardrails/rules/)). **Where it exceeds gove-zone:** A6 (managed injection/PII/secrets/toxicity/copyright detectors), framework-integration breadth, and enterprise backing via the Snyk acquisition. **Where gove-zone differs:** Invariant has no authority model (API-key auth only), no tamper-evident audit, and no portable verifiable receipt; its multi-step rules are reactive pattern-matching over observed sequences, not pre-authorization of a declared plan.

**Permit.io AI Access Control (+ Oso)** *(suite — fine-grained authz + MCP gateway; GA, SOC 2 Type II).* An action-time PDP (RBAC/ABAC/ReBAC, Oso Polar) plus a drop-in MCP gateway that allows/denies/escalates every tool call with identity binding and human-in-the-loop approval ([HITL docs](https://docs.permit.io/permit-mcp-gateway/human-in-the-loop)). **This is gove-zone's closest peer on authority.** **Where it exceeds gove-zone:** A8 maturity (GA, SOC 2 Type II / HIPAA, managed control plane, OAuth 2.1, out-of-box GitHub/Slack/Jira integrations, polished approval UI) and richer native authz modeling — versus gove-zone's alpha Unix-only library. On A2 the two are **comparable**: Permit has a real distinct-approver + expiry flow; gove-zone has structural proposer≠validator rejection. **Where gove-zone differs:** Permit's audit is a complete trail but **not** documented as hash-chained/tamper-evident (A3=partial), and it has **no documented portable verifiable replayable receipt** (A4=**unknown**, transcribed as such); its governance is per-call + request-lineage *visibility*, not enforced governance over a workflow as a unit.

**Azure AI Content Safety — Microsoft Foundry guardrails** *(point solution — content-safety guardrail; GA core, agent guardrails Preview).* Cloud-managed classifiers scan agent inputs, tool calls, tool responses, and outputs and block on detection ([overview](https://learn.microsoft.com/en-us/azure/foundry/guardrails/guardrails-overview)). **Where it exceeds gove-zone:** A6 (GA jailbreak/indirect-injection/PII/grounding/protected-material classifiers) and A8 (Azure SaaS, Entra RBAC, monitoring, Government path). **Where gove-zone differs:** Foundry's RBAC governs *who configures* guardrails (management plane), not per-action authority (A2=no); its audit is Azure Monitor logging, not hash-chained (A3=partial); and every control acts at a single per-call intervention point — no plan-level governance (A7=no).

**OpenAI Agents SDK Guardrails** *(point solution — in-framework guardrails; GA library).* Tool-input guardrails run before a function tool executes and can skip / replace / tripwire, with first-party content-safety detectors via `openai-guardrails` ([guardrails docs](https://openai.github.io/openai-agents-python/guardrails/)). **Where it exceeds gove-zone:** A6 (first-party moderation/jailbreak/injection/PII detectors) and A8 (GA, widely-adopted, Python+TS). **Where gove-zone differs:** policy is procedural code (A5=no), approval is application-level with no identity/expiry (A2=partial), and both tamper-evident audit and verifiable receipts are **undocumented** (A3=**unknown**, A4=**unknown** — transcribed verbatim, not collapsed to "no"); governance is per-call, not plan-level.

**Guardrails AI** *(point solution — inline LLM I/O guardrails; OSS pre-1.0 + Pro platform).* Guards composed of Hub validators that detect/mitigate content risks and return validated output ([guard docs](https://guardrailsai.com/docs/concepts/guard)). **Where it exceeds gove-zone:** A6 (a broad managed validator library — advanced PII/PHI, a jailbreak model, multi-category toxicity) and ecosystem maturity (OTel/Prometheus/Grafana/MLflow). **Where gove-zone differs:** Guardrails AI gates the *LLM prompt/response*, not an arbitrary downstream side effect (A1=partial); it models no authority (A2=no), keeps only in-memory history (A3=no), and has no plan-level governance.

**Lakera Guard** *(point solution — real-time content-safety guardrail; GA, SOC-2).* A real-time content-safety screen (SaaS or self-host) returning a flag the caller enforces ([guard](https://docs.lakera.ai/guard)). **Where it exceeds gove-zone:** A6 (managed injection/jailbreak/PII/toxicity/malicious-link detectors) and A8 (GA, SOC-2, GDPR, SaaS + air-gapped self-host, RBAC). **Where gove-zone differs:** Lakera *advises* (returns a flag; the caller enforces) rather than intercepting and enforcing (A1=partial); it models no runtime action authority (A2=no), logs are not hash-chained (A3=partial), and the `request_uuid` artifact carries no signature/replay (A4=partial); single-step only.

**Pillar Security / Lasso Security** *(point solution — content-security guardrails for MCP/agent runtimes; Pillar GA SOC 2 Type II + OSS gateway).* Managed injection/PII/secret/egress detection that blocks at pre/post tool-invoke ([platform](https://www.pillar.security/platform)). **Where it exceeds gove-zone:** A6 (injection/harmful-content/PII/secret + source-to-destination taint egress) and A8 (GA, SOC 2 Type II, LiteLLM/TrueFoundry breadth). **Where gove-zone differs:** Pillar/Lasso enforce permission analysis but no per-action authority unit with scoping/expiry (A2=partial), log to mutable SQLite/DuckDB (A3=no), and ship no portable verifiable receipt; multi-step is behavioral observability, not governance of a declared plan.

## Where gove-zone is genuinely distinctive

The distinctiveness is **architectural and integration-posture**, not maturity or breadth. Three properties, bundled behind **one invariant** — *"no valid Decision Receipt, no side effect"*:

1. **One enforced gate that fuses authority + audit + receipt + plan.** Almost every competitor is a *point solution*: guardrails **or** authz **or** audit **or** observability. gove-zone makes a single pre-side-effect call carry all four — a verdict (ALLOW/DENY/TRANSFORM/ESCALATE), an authority decision (validator≠proposer), a hash-chained audit append *before* execution, and a verifiable receipt — and fails closed at every step (policy raises → synthesized DENY; audit append fails → `AuditError`; policy timeout → DENY; never a silent allow).
2. **MACI proposer≠validator separation, structurally rejected at issuance.** `receipt.py` refuses to mint a receipt when `validator.validator_id == proposer` ("self-validation forbidden"), and the gate requires a caller-anchored `expected_actor`. Permit.io reaches comparable separation via a *runtime HITL approver*; gove-zone's is a *type/role boundary at receipt construction*. Honest caveat: principals are **opaque caller-supplied strings** (the check proves *distinctness of strings*, not authenticated identity), and the separation is **enforced-by-verifier + audited, not cryptographically unforgeable by default** (signing is opt-in/off).
3. **Plan-level governance as a first-class unit (A7).** `WorkflowDAG` issues per-step receipts with ledger ordering, and `WorkflowAuthorization` enforces plan-proposer≠plan-validator with cross-level MACI separation — a reordered or cross-workflow step cannot fire ahead of its rejection. The narrowest competitor gap is Invariant Labs, whose gateway *can* enforce tool ordering pre-execution; what no surveyed competitor does is authorize a **declared plan/DAG as a unit** with plan-proposer≠plan-validator separation. Honest caveat: ordering and anti-replay are enforced **per single in-memory run via a trusted ledger** (no cross-process / persistent enforcement; envelopes unsigned by default); offline `verify_workflow_replay` proves topological consistency, not unforgeability. gove-zone is also the only row that is **yes** on hash-chained tamper-evident audit (A3) — scoped as above: in-place edits, not a full re-hash.

These are capability claims, **not** maturity claims. Even on A3 and A7, the competitors are more mature operationally; gove-zone's edge is that it bundles these behind one gate as a self-hostable substrate, not that it is more production-ready. (One corroborating market signal surfaced during verification: every "cryptographic receipt for guardrails" we found — *Proof-of-Guardrail* and similar — is an *external third-party overlay* bolted onto these vendors, not a native feature, which is part of why no competitor reaches **yes** on A4.)

## Where gove-zone is behind

This is substantive, not a token nod:

- **Maturity (A8).** gove-zone is **beta 1.0.0rc1**, explicitly not production- or compliance-certified. Bedrock, Azure Foundry (core), Permit.io+Oso, Lakera, OpenAI Agents SDK, NeMo, LlamaFirewall, and Pillar are all GA or GA-grade, several with SOC 2 Type II / HIPAA / FedRAMP / GDPR posture. gove-zone has none of that.
- **Content safety (A6).** gove-zone ships **zero** prompt-injection / jailbreak / PII / toxicity classifiers. If your need is "detect and block unsafe *content*," essentially every guardrail vendor here is a better fit out of the box — you would have to bring or build the classifier yourself and express it as a gove-zone policy.
- **Unsigned by default → bounded tamper-evidence.** Cryptographic signing is opt-in and **off** by default (`NullSigner` → `"unsigned_local"`); there is no PKI, no key distribution, no revocation. A "valid" receipt in a default deployment is integrity-and-policy-valid, not signature-valid — and the hash-chained audit catches in-place edits but a *full* downstream re-hash is caught only with an external anchor or signing.
- **Observer-by-default.** The runtime-hook adapter emits `ALLOW` unless the integrator wires a custom `Policy` plus `enforce` mode. Out of the box it *records*; it does not *block*. Enforcement is real but integrator-configured, not a default.
- **Replay is bounded (A4).** Replay verifies chain integrity + event presence + policy-version match — **not** full policy re-derivation, because the audit stores only an `argument_hash`, never the raw arguments ("cannot re-derive without raw args"). Several competitors lack any receipt at all, but gove-zone's is honestly *partial*, not complete.
- **Deployment & integration breadth.** Self-host, Unix-only (`fcntl.flock`), no SaaS, no managed control plane, and far narrower out-of-box integrations than Permit.io's MCP gateway, Bedrock/Azure's cloud ecosystems, or NeMo's K8s/NIM and LangChain breadth.

## Method & limits

- **gove-zone is source-verified** against `packages/gove-zone/src/gove_zone/*.py` (notably `kernel.py`, `receipt.py`, `signing.py`, `replay.py`, `audit.py`, `policy.py`, `workflow.py`, `plan.py`) plus README / ARCHITECTURE / SECURITY. The fail-closed behavior, the validator≠proposer rejection, the `NullSigner` default, the bounded-replay scope, and the absence of any content classifier were each confirmed in code.
- **Every competitor cell is from published vendor documentation only.** We could not run their code. Each cell records what the docs state; where docs neither confirm nor deny a property the cell reads **unknown**, not "no." Confidence was tracked per axis during verification (high/medium/low) and the most uncertain claims are exactly the **unknown** cells. Vendor docs change — these readings are a point-in-time snapshot and may be stale; re-verify against the linked primary sources before relying on any single cell.
- **Two-directional adversarial verification** was applied to competitor claims (look for evidence the property exists *and* evidence it does not) before assigning each status; statuses here reflect the adjusted result, not first-pass marketing copy.

### Note on adjacent tools considered, not ignored

**LangSmith / LangChain observability + evals** was evaluated and **excluded** because it fails the inclusion gate: it records traces of what an agent *already did* and scores them after the fact (online evaluators run on production traces post-execution); it does not intercept a call inline to return allow/deny. Its only runtime-pause feature (human-in-the-loop approvals) is a LangGraph deployment capability, a manual pause rather than a programmatic policy-decision-with-evidence on the observability surface. That is an after-the-fact eval harness, not a pre-side-effect gate.
